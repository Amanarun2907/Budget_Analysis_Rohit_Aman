1. PROJECT OVERVIEW & EXECUTIVE SUMMARY
====================================================================================================
The Budget Intelligence Platform is a comprehensive, production-grade, full-stack economic analysis
system designed to interpret, dissect, reconcile, and visualize the Union Budget of India and all
state government budgets across any financial year.

Government financial documents (Budget Speeches, Annual Financial Statements, Demands for Grants,
Receipt Profiles, Expenditure Profiles, Fiscal Policy Statements, and Economic Surveys) are
notoriously dense, multi-hundred-page publications containing complex accounting terminology,
multilateral deficit definitions, and thousands of numerical figures.

This platform bridges the gap between public finance documents and actionable economic intelligence.
It functions as a collaborative team of a Senior Chief Economist, Public Finance Auditor, Data
Scientist, and Visualization Designer:
- Ingests multiple unstructured budget documents (PDFs, Scanned PDFs, Excel, Word, Images, Text).
- Performs layout segmentation, table extraction, and OCR.
- Orchestrates an 8-agent AI specialist pipeline on the Groq LPU engine.
- Enforces strict deterministic financial validation so every figure reconciles with accounting laws
  (e.g., Fiscal Deficit = Total Expenditure - Non-Debt Receipts).
- Delivers an interactive, 7-tab dashboard with charts, KPI cards, tables, and AI explanations.
- Features a conversational AI Copilot grounded in document citations with page references.
- Exports publication-grade PDF dossiers, multi-tab Excel workbooks, CSV datasets, and JSON APIs.

4. BACKEND SERVICE ARCHITECTURE & DATA MODELS
====================================================================================================

4.1. Database Engine & Relational Models
----------------------------------------------------------------------------------------------------
Location: backend/app/models/budget.py
The database uses SQLAlchemy 2.0 with asynchronous support (aiosqlite for zero-setup local execution,
with seamless configuration for postgresql+asyncpg for enterprise deployment).

Primary Tables:
1. `budget_workspaces`:
   - Primary entity representing an uploaded budget analysis workspace.
   - Fields: id, name, government_level (union/state), state_name, financial_year, description,
     processing_status, processing_progress, analysis_completed, analysis_result (JSON),
     executive_summary, budget_highlights (JSON), total_receipts, total_expenditure,
     fiscal_deficit, revenue_deficit, timestamps.
2. `budget_documents`:
   - Tracks individual files uploaded to a workspace (Speech, Receipts, Grants, etc.).
   - Fields: id, workspace_id, filename, original_filename, file_path, file_size, file_type,
     document_type, page_count, processing_status, extracted_text, extracted_metadata (JSON).
3. `financial_entries`:
   - Normalized line items for granular SQL querying.
   - Fields: id, workspace_id, category, sub_category, item_name, amount (₹ Crore), unit,
     estimate_type (BE/RE/Actual), ministry, department, sector, source_page, confidence_score.
4. `sector_analyses`:
   - Sector-specific entries (Agriculture, Defence, Education, etc.).
   - Fields: id, workspace_id, sector_name, total_allocation, previous_allocation,
     percentage_of_total, yoy_change, key_schemes (JSON), analysis_text, highlights (JSON).
5. `scheme_analyses`:
   - Welfare and developmental scheme records.
   - Fields: id, workspace_id, scheme_name, ministry, department, sector, current_allocation,
     previous_allocation, yoy_change, objective, beneficiaries, analysis_text, is_new, is_discontinued.
6. `chat_messages`:
   - Persistent conversation log for the AI Copilot.
   - Fields: id, workspace_id, role (user/assistant), content, sources (JSON), created_at.

4.2. Document Ingestion, OCR & Extraction Pipeline
----------------------------------------------------------------------------------------------------
Location: backend/app/services/document_processing/processor.py
The ingestion engine extracts raw text, tables, and metadata across heterogeneous document types:
- PDF & Scanned Documents: PDFPlumber extracts structured text and table grids with bounding boxes;
  PyPDF extracts fallback text streams; Tesseract OCR handles scanned raster pages.
- Spreadsheets: openpyxl and csv parsers convert multi-sheet budgets into structured JSON matrices.
- Word Processing: python-docx extracts headings, bullet hierarchies, and table objects.
- Automatic Metadata Detection:
  - Scans for regex patterns like "Union Budget", "Government of India", "Annual Financial Statement".
  - Matches 36 Indian States and Union Territories (Uttar Pradesh, Maharashtra, Tamil Nadu, Bihar, etc.).
  - Extracts financial year syntax: "2024-25", "2024-2025", "2025-26".

4.3. Multi-Agent AI Economic Intelligence System
----------------------------------------------------------------------------------------------------
Location: backend/app/services/analysis/budget_agents.py
Instead of a monolithic prompt, the system deploys an 8-agent specialized public finance team:
- Agent 1 (Overview Agent): Synthesizes top-line receipts, outlays, deficits, and writes the executive narrative.
- Agent 2 (Receipts Agent): Dissects tax streams (Direct: Income, Corporation; Indirect: GST, Customs, Excise)
  and non-tax revenue.
- Agent 3 (Expenditure Agent): Analyzes capital outlay versus revenue expenditure, committed liabilities,
  and ministry rankings.
- Agent 4 (Fiscal Health Agent): Calculates deficit ratios, assesses FRBM compliance, and projects debt trends.
- Agent 5 (Sectoral Economist Agent): Evaluates sectoral resource allocation and strategic priority shifts.
- Agent 6 (Scheme Analyst Agent): Evaluates flagship missions, centrally sponsored schemes, and beneficiaries.
- Agent 7 (Macroeconomic Strategist): Analyzes GDP growth assumptions, inflation outlook, and capex multipliers.
- Agent 8 (Audit & Quality Agent): Evaluates completeness, consistency, and validates data integrity.

4.4. Deterministic Financial Validation & Math Engine
----------------------------------------------------------------------------------------------------
Location: backend/app/services/analysis/orchestrator.py
To guarantee mathematical perfection and zero hallucinations:
- `_safe_float()` Normalizer: Strips currency signs (₹, $), commas (e.g., "48,20,512"), and units ("Cr", "Crore", "%")
  preventing runtime string-conversion errors.
- Accounting Reconciliation Rules:
  1. Total Budget Outlay = Revenue Outlay + Capital Outlay
  2. Gross Fiscal Deficit = Total Outlay - (Revenue Receipts + Non-Debt Capital Receipts)
  3. Primary Deficit = Gross Fiscal Deficit - Interest Servicing Obligations
  4. Deficit-to-GDP Ratio = (Gross Fiscal Deficit / Nominal GDP) * 100

4.5. ChromaDB RAG Engine & Hybrid Vector Store
----------------------------------------------------------------------------------------------------
Location: backend/app/services/rag/vector_store.py & chat_engine.py
- Chunks text into 1,000-character segments with 200-character overlap while preserving page markers.
- Stores embeddings in ChromaDB with cosine distance metric.
- Implements a resilient local JSON chunk repository with keyword relevance scoring and direct citation
  lookup, guaranteeing uninterrupted functionality without telemetry friction.

4.6. Multi-Format Report Generator
----------------------------------------------------------------------------------------------------
Location: backend/app/services/report/report_generator.py
- PDF Dossiers: Built via ReportLab with formal cover page, executive summary, KPI tables, and sector matrices.
- Excel Workbooks: Generated via openpyxl with multiple dedicated sheets ("Overview", "Sectors", "Schemes").
- CSV Datasets: Comma-separated files formatted for import into Stata, R, Excel, or Python.
- JSON Export: Complete REST-compliant payload for programmatic access.

7. AI ENGINE CONFIGURATION & ZERO-HALLUCINATION PROTOCOL
====================================================================================================
The platform utilizes the Groq Language Processing Unit (LPU) architecture for sub-second inference:

Primary Model:
- `qwen/qwen3.8-27b`
  - Verified benchmark latency: 1.28 seconds for complete structured budget queries.
  - 100% adherence to valid JSON objects using `response_format={"type": "json_object"}`.
  - High mathematical precision on Indian accounting subtraction and ratios.

Secondary Fallback Models:
- `openai/gpt-oss-120b`: 120-Billion parameter large model for narrative depth.
- `openai/gpt-oss-20b`: High-speed fallback.

Zero-Hallucination Safeguards:
1. Candidate Model Selection Loop: Automatically iterates through available models to prevent 404/400 errors.
2. Grounded Evidence Context: Prompts inject verified document text chunks with source page markers.
3. Fallback Deterministic Reconciler: If any LLM fails or returns incomplete values, deterministic
   subtotal calculators compute figures directly from document text.
4. Citation Integrity: The chat engine returns snippet text and page citations so users can verify every figure.
